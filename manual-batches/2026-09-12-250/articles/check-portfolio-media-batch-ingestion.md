Check a company's media batch before library admission by reconciling the submitted files with a receipt, verifying company identity and required context, and assigning each item an accept, return or hold decision. Upload success is not acceptance. Use a batch register that keeps missing captions, uncertain release instructions and cross-company material out of the active collection.

## Define the admission boundary

This workflow handles recurring new submissions from portfolio companies. It is not a migration of an existing library or a supplier procurement checklist. The company is sending its own media into a shared operating system, and the platform must decide what can enter the maintained collection.

Define what admission means. It may establish that a file is identifiable, complete enough to catalog and suitable for the intended access area. It should not automatically mean that the file is approved for public publication or every future use.

[Bynder's upload guidance](https://support.bynder.com/hc/en-us/articles/24265123462418-Guide-to-Uploading-Assets-in-Bynder) describes upload routes with review and metadata handling. The practical lesson is to distinguish receipt from controlled admission. Your program can use a simple register even if its storage system has no built-in acceptance workflow.

State the required submission context before companies send files. At minimum, identify the company, contact, intended use, asset descriptions and the source of relevant release instructions. Requirements should reflect the actual media type rather than one oversized form for every submission.

## Ask for a batch receipt that can be reconciled

Give the submission a batch ID and ask for a list of intended files. Record the sender, company ID, submission date, expected item count and any relationship among files. A caption file should identify its corresponding video rather than relying on a similar filename.

Keep the company's descriptions with the batch. A file called “final2.mp4” does not explain its subject, audience or current approval state. The receipt should supply enough context for the platform to ask a precise question if something is missing.

[Bynder's taxonomy guidance](https://support.bynder.com/hc/en-us/articles/20331272932626-Taxonomy-Tips-for-your-DAM) connects metadata choices with how users search. At admission, apply the existing dictionary consistently. Do not redesign the taxonomy for every incoming batch or let uploaders create new categories merely to bypass a required field.

Make the distinction between missing and not applicable explicit. A silent logo file does not need a spoken-language field; a recorded interview with an unidentified language has a different problem. The receipt should allow the operator to express that difference.

## Work through a five-item fictional batch

Suppose Alder submits batch B-204 containing a founder interview, its captions, a portrait, a product capture and an event photograph. The company's receipt lists all five items.

| Item | Receipt expectation | Check result | Decision | Return or hold condition |
| --- | --- | --- | --- | --- |
| V-21 interview | Final company-approved export | File and approval reference match | Accept into Alder collection | Public reuse still follows stated instructions |
| C-21 captions | Captions for V-21 | Timing corresponds to an earlier export | Return | Supply captions matched to V-21 |
| P-21 portrait | Founder portrait with supplied credit | Credit wording absent | Hold | Company supplies or confirms the credit |
| S-21 product capture | Current product screen recording | Company and subject clear; marked working | Accept into working area only | Keep out of released-asset discovery |
| E-21 event photograph | Alder event image | Includes another company's restricted session context | Hold | Relevant owner resolves inclusion and audience |

The batch receipt reconciles five expected items with five received items, but only two are accepted into their specified areas. Counting files alone would miss three unresolved decisions.

Record the evidence behind each result and the owner of the next action. C-21 needs a replacement file from the sender. P-21 needs a factual or instruction confirmation. E-21 needs a scope decision that the intake operator should not make by guessing.

## Check the relationships as well as individual files

Open or preview files through the program's normal safe inspection process. Confirm that the contents match the receipt, the media can be used in the expected workflow and companion files belong together. A successful transfer does not establish that the file is the intended version.

For video, compare the caption timing with the actual export and inspect enough content to identify obvious mismatches. For photographs, check the supplied scene description, people record and credit context. For editable material, record missing dependencies rather than assuming that every recipient has them.

Check company separation at both batch and item level. A submission from an authorized Alder contact can still contain a shared event file or another company's asset. Sender identity does not make every included item company-specific.

Do not silently repair material in ways that change its meaning or use conditions. Renaming a file to fit the library convention may be a routine recorded action; rewriting a caption, changing an approval state or removing a person from an image requires the appropriate review.

## Return a decision receipt, not a vague rejection

Send the company an itemized response using the same batch and asset references. State what was accepted, where it went, what was returned and what remains on hold. Give a specific next action for each unresolved item.

For C-21, ask for captions corresponding to the named V-21 export and explain that the current file is misaligned. For P-21, ask for the exact supplied credit wording or a clarification from the appropriate source. Avoid a generic “metadata incomplete” message that forces the company to guess.

Keep accepted items stable when the company resubmits corrections. The next receipt should identify which rows it replaces, rather than creating a second competing batch of all five files. Check the changed items and any affected relationships.

If the company cannot resolve a requirement, identify an alternative disposition with the relevant owner. The portrait may remain unavailable for the intended placement, or a different approved event image may be used. Do not fill missing evidence with an invented value to finish the batch.

## Close admission without implying publication approval

Mark each row closed when its admission decision and destination are recorded or its return or hold has an accepted resolution. Keep unresolved rows visible even when the rest of the batch is useful.

Verify the final collection view from the intended audience. Accepted working material should not appear beside released assets without a clear distinction. Check that the company can find the accepted items and that unrelated companies cannot access restricted material through the new placement.

Review repeated returns to improve the submission instructions. If caption mismatches recur, provide a clearer companion-file example. If supplied credits are often missing, show where the sender should include them. The improvement should address the observed gap rather than add unrelated mandatory fields.

The completed work product is a reconciled batch receipt with item-level decisions and traceable next actions. It lets a portfolio media library admit useful new material while keeping upload, cataloging, release and cross-company access as distinct decisions.
