Keep an uncut product take behind your investor demo so a shortened scene can be traced to one complete recorded run. Preserve the starting state, intervention and actual result, then map each presentation interval back to its source. The record supports inspection; it does not prove everything happening outside the camera’s view.

## Define what one continuous take will establish

Choose the claim the source recording needs to support. For a fictional invoice-matching product, the take might show one sample invoice entering the workflow, a proposed match appearing and a human confirming the result. The continuity claim concerns that recorded sequence.

State where the recording begins and ends. If authentication, sample preparation or a previous calculation happens before capture, note it. An uncut movie that starts after the difficult step does not show the complete workflow merely because there are no visible edits.

Record the environment and run identity privately. Include the product build, sample identifier and relevant starting state. Use a simple run label such as invoice-demo-run-C, not a label implying independent verification or certification.

Decide whether sound is part of the evidence. An off-camera instruction or product alert may explain an action that would otherwise appear automatic. Preserve relevant audio in the source take, even if the investor-facing cut uses a separate explanatory narration.

## Capture enough context around the decisive action

Begin before the initiating action and leave enough time afterward to inspect the result. Avoid stopping the capture immediately when a success banner appears. Show the actual output or changed state that supports the stated completion criterion.

Keep retries, corrections and human assistance in the source. If a person changes an input or approves a result, record that intervention clearly. The later presentation cut may shorten navigation, but it should not transform an assisted sequence into apparently autonomous behavior.

If several cameras or screen recordings cover the same run, preserve their individual files and a shared synchronization landmark. [Apple’s synchronization guidance](https://support.apple.com/en-ie/guide/final-cut-pro/verc1fabc30/mac) describes aligning clips from one take. Alignment connects views; it does not make footage from different executions into one continuous run.

Write down any capture interruption immediately. A stopped recorder, missing audio interval or device restart is a discontinuity, even if the product continued operating. Keep the note with the source rather than relying on a founder to remember it weeks later.

## Map presentation time back to source time

Build this original evidence edit decision list as you create the investor cut. Each row names the presentation interval, source file, source interval and reason for the edit.

| Final interval | Source reference | Source interval | Treatment and meaning |
| --- | --- | --- | --- |
| 00:00–00:10 | invoice-demo-run-C.mp4 | 00:05–00:15 | Context retained; opening setup omitted and disclosed |
| 00:10–00:18 | invoice-demo-run-C.mp4 | 00:15–00:23 | Initiating action at normal speed |
| 00:18–00:24 | invoice-demo-run-C.mp4 | 00:23–00:53 | Thirty-second wait shown in six seconds; label required |
| 00:24–00:36 | invoice-demo-run-C.mp4 | 00:53–01:05 | Human confirmation and result retained |
| 00:36–00:42 | Editorial end card | No product source interval | Illustration or explanation, not captured execution |

These are fictional timecodes illustrating the mapping. Use actual intervals from your own run. The six-second wait representation is edited playback, not a claim that the product completed its operation in six seconds.

[Apple’s Final Cut Pro specifications](https://www.apple.com/my/final-cut-pro/specs/) list separate project and source-timecode display. Use the equivalent information in your editor, or a carefully maintained manual ledger. Always identify which clock you are citing; the same number can refer to different moments in the source and final cut.

## Make discontinuities explicit in the presentation

Review every transition in the final cut and ask what continuity the viewer will infer. A cut from a typed input to a result can suggest immediate processing. A switch between devices can suggest both views belong to the same run. Confirm those interpretations or label the difference.

Do not insert a cleaner output from another run without identifying it. If the presentation needs a separate explanatory example, mark the scene as such and give it its own source reference. A beautiful sequence is less useful when its evidence trail depends on hidden substitutions.

Distinguish illustrative overlays from the product’s captured interface. A diagram explaining an operation should not look like a live status indicator generated by the product. Note the overlay in the edit decision list so a reviewer can understand what was added.

Keep disclosure attached to the affected interval when it changes the meaning. A private source note cannot help an investor who only watches the shortened clip and reasonably interprets an omitted human action as automation.

## Test the evidence trail with a permitted reviewer

Give a colleague the final cut and ledger without narrating the edit history. Ask them to find the source moment behind a selected result, then play enough surrounding footage to understand how it arose.

Have them check the sample identifier, action and output across the mapping. If the final scene points to the right timestamp but the wrong run, the ledger has failed its job. Correct the reference and repeat the trace.

Ask what the source still cannot establish. Perhaps the camera does not show a separate operator, or the recording cannot confirm the state of an external system. Write those limits honestly rather than treating “uncut” as a synonym for independently proven.

Keep the exercise proportionate to the claim. A source trace for one investor demonstration is not a benchmark, security audit or universal reliability study. Its value is that an appropriate reviewer can inspect the recorded evidence behind the edited presentation.

## Prepare an access-controlled source handoff

Preserve the original source files separately from presentation exports. Keep the run notes and ledger with them. Avoid overwriting the source with a version that has already been trimmed, masked or narrated over.

Review permission and sensitive content before offering the uncut take to an investor. The source may contain material that was appropriately excluded from the presentation copy. A request for more evidence does not automatically authorize sharing every raw recording.

When sharing is appropriate, send the exact source reference and the interval relevant to the question, with enough context to interpret it. If only a treated reference copy can be shared, describe that treatment and do not call it the untouched original.
