Keep portfolio resource translations in sync by linking every language version to its source, classifying each source change and assigning a review action for the affected translations. Track article text, navigation labels and linked files separately. A translation should not appear current merely because its page remains live after the original guidance changes.

## Establish a source relationship for each resource

Start with the maintained resource, not a list of languages. Give the source article or guide a stable identifier and identify the owner who can approve changes. Each translated version should point to that source and record the revision it last incorporated.

A language page may remain useful even when it needs review. The important distinction is whether the change affects a reader's next action. A corrected spelling and a replaced submission route have different consequences. The operator needs enough information to choose the appropriate handling.

[Zendesk documents marking translated articles as outdated](https://support.zendesk.com/hc/en-us/articles/4408821505306-Managing-help-center-translations-for-articles). The operational principle is to make stale status explicit instead of assuming that all language versions update together. Your own system may represent that state through a field, label or review register.

Keep translation status separate from company approval and access. A fully translated resource may still be restricted to one cohort. A company-approved source may have an unchecked translation. Those states answer different questions and should not collapse into one “ready” label.

## Classify changes by their effect on use

When the source changes, record what changed and why. Useful categories include editorial wording, factual correction, changed instruction, replaced link and removed material. A category is a triage aid, not an automatic decision about whether translation review can be skipped.

Ask whether the translated resource still gives a correct path to completing the task. If a media-submission form has moved, a translation pointing to the old form may block users even when every paragraph remains accurate. If a new eligibility rule has been approved, the old language version may direct the wrong audience to request help.

Identify affected components beyond the article body. [Zendesk treats category and section translations separately](https://support.zendesk.com/hc/en-us/articles/4408821388442-Managing-translations-for-categories-and-sections), including their own outdated status. A corrected article can still be difficult to find when its translated navigation label or parent description remains stale.

Also check attached worksheets, screenshots, captions and confirmation messages. The goal is a coherent resource path for the user, not a language page whose main text passes review while its download leads elsewhere.

## Populate a translation change register

Imagine a fictional portfolio guide, RES-12, explaining how companies submit approved media. Its English source changes from revision 3 to revision 4 because the submission route and required company contact field have changed.

| Component / language | Last incorporated revision | Change impact | Owner | Required action |
| --- | --- | --- | --- | --- |
| English source article | 4 | Approved new instruction | Resource owner | Source ready |
| Spanish article | 3 | Old form link and missing contact field | Spanish reviewer | Update instructions and test the new route |
| French article | 3 | Same instruction gap | French reviewer | Mark review pending; follow the program's interim display policy |
| Spanish navigation label | Separate label revision | Still says “Upload files” when task now includes a receipt | Navigation owner | Review label against the actual task |
| Multilingual checklist PDF | Based on revision 3 | Required field absent | Worksheet owner | Replace after language review |

The register adds source-change reference, date, reviewer confirmation and published destination. It does not assume that the language reviewer owns the website navigation or attached worksheet. Those dependencies require named handoffs.

For the French article, the operator chooses an interim action with the resource owner. That might be a clear update notice, a link to an appropriate maintained alternative or a temporary hold on the affected instructions. The decision depends on the task's risk and the audience's needs, not a universal rule to remove every outdated page.

## Give reviewers the change context

Send a compact review packet containing the old passage, new passage, reason for change, affected links and expected user action. A reviewer should not have to compare two long documents to discover that one form field changed.

Distinguish terminology decisions from literal wording. A company role or media asset type may have an established translation used across the portal. Provide that vocabulary where it exists and ask the reviewer to flag a term that no longer fits. Do not automatically replace consistent terminology with a new machine-generated phrase.

Use automated translation only within the organization's approved workflow and with appropriate review for the intended use. This article does not assume a particular tool, supported language or quality level. The accountable owner still needs evidence that the final instructions are understandable and accurate.

Keep reviewer questions attached to the component they affect. A question about a screenshot should not silently block an unrelated navigation correction, but a question about the submission eligibility rule may affect every language version.

## Test the complete language path

After the update, ask a reviewer to follow the resource as a user would. Start from the translated navigation, open the article, follow its links and inspect the worksheet. Check that the language version explains the same required action as the maintained source.

For RES-12, the test ends when the reviewer can identify the correct form and the required company contact field. It does not require submitting real company files merely to prove the link works. Use the normal safe preview or test process where available.

Verify that the published page corresponds to the reviewed revision. A reviewer may approve the correct text while an older copy remains live. Record the checked destination and review evidence so “translation complete” means more than a document was returned.

Check fallback behavior when a language component is unavailable. A user should not encounter a navigation label in one language, outdated instructions in another and an unexplained download in a third. State the maintained alternative clearly rather than allowing accidental mixtures.

## Close changes without losing the next trigger

Close each component when the relevant reviewer confirms the published result and the register records the source revision incorporated. Keep outstanding components visible, even if the main article has been updated.

Review recurring causes of drift. Perhaps source owners do not notify language reviewers, screenshots are stored outside the change register or navigation labels have no owner. Repair the missing relationship rather than relying on a full translation audit after every change.

Keep the register modest. It needs to answer which source changed, which versions depend on it, what action is required and whether the published path was checked. It does not need to become a second content repository.

The final work product is a source-to-language change map with explicit review and publication states. It helps portfolio companies follow current media instructions in the language offered to them without treating a live translation as proof that its guidance remains current.
